# 输出模式

当技能需要稳定地产出高质量结果时，使用以下模式。

## 模板模式

为输出提供模板，并根据任务需要选择约束强度。

**适用于 API 响应或数据格式等严格要求：**

```markdown
## 报告结构

必须严格使用下面的模板：

# [分析标题]

## 执行摘要

[用一个段落概述主要发现]

## 主要发现

- 发现 1 及其支撑数据
- 发现 2 及其支撑数据
- 发现 3 及其支撑数据

## 建议

1. 明确且可执行的建议
2. 明确且可执行的建议
```

**适用于需要按实际情况调整的灵活指引：**

```markdown
## 报告结构

以下是合理的默认格式，可根据实际发现调整：

# [分析标题]

## 执行摘要

[概述]

## 主要发现

[根据发现调整章节]

## 建议

[结合具体上下文编写]

根据分析类型按需调整章节。
```

## 示例模式

如果示例能显著提升输出质量，应提供输入与输出配对：

```markdown
## 提交消息格式

按以下示例生成提交消息：

**示例 1：**
输入：增加基于 JWT 的用户身份验证
输出：
```

feat(auth): 实现基于 JWT 的身份验证

增加登录端点和令牌验证中间件

```

**示例 2：**
输入：修复报表日期显示错误
输出：
```

fix(reports): 修正时区转换中的日期格式

生成报表时统一使用 UTC 时间戳

```

遵循 `type(scope): 简短说明` 的格式，并在下一段补充详细解释。
```

与单纯描述相比，示例能让智能体更准确地理解目标风格和细节层级。
